# 已知风险清单

核验基准：2026-10-29。范围为当前本机合成数据演示，不是面向真实银行或线上服务的安全评估报告。以下包含已知限制、设计取舍和未覆盖验证项；不把“测试通过”表述为风险消除。

优先级约定：**P0** 表示扩展为真实服务前必须重新设计的阻断项；**P1** 表示影响演示结果、保密性或完整性的主要限制；**P2** 表示工程和可用性改进。P0 不表示当前虚构演示已经造成真实资金损失。

## 验证与复查流程

1. 在干净源码目录运行 `python -X utf8 -m unittest discover -s tests -v`，保留平台、Python 版本、时间、实际通过/失败数量。当前实现基线为 162 项，若新增测试则按实际结果记录。
2. 用前端手工核对新收款人 2888 元首次弹窗/取消/确认/列表，已核对人再次小额直转，3000 元摘要确认；只使用虚构信息。
3. 复核日志失败、报价变化、认证切换、风险升级、重复请求和未知状态查询的专测，确认没有为演示方便删除后端检查。
4. 若变更认证、Cookie、监听地址、工具适配器、持久化、直接执行条件或范围授权，重新审查信任边界，并更新此清单与[权限文档](权限分级实现.md)。

未进行：外部渗透测试、自动化浏览器安全扫描、广泛模糊测试、真实网络故障/数据库故障测试、独立代码审计或生产金融合规认证。风险清单的“建议”均为后续方案，没有在当前代码中实现。
