# 安全设计

核验基准：2026-10-29；适用范围：当前仓库的本机虚拟银行教学原型。本文说明代码中已经存在的控制，并与尚未实现的能力分开。该程序没有真实银行、证券、实名认证或消息服务连接；所有交易都只修改本轮合成数据。

相关文档：[权限分级实现](权限分级实现.md) · [已知风险清单](已知风险清单.md) · [系统架构](系统架构.md)

## 1. 安全目标与适用假设

当前目标是避免演示中的误操作、重复扣款、跨浏览器会话串数据、跨站提交和错误状态展示，使学生可以观察一个有状态、可审计的业务流程。安全控制覆盖输入、认证、风险、预览、授权、执行和状态核验；没有把自然语言解析结果直接当成执行权限。

假设运行机器、Python 程序文件和工具适配器由演示者控制；浏览器提供正常的同源与 Cookie 保护。恶意本机程序、有管理员权限的人、被修改的 Python 代码或恶意浏览器扩展不在这些本机网页控制的可防御范围内。

主要资产包括本轮账户与持仓状态、任务与确认摘要、会话 Cookie/CSRF token、收款人列表、计划授权范围，以及本地审计文件。资产都是虚构样例；用户自行输入的聊天文本仍可能包含其个人信息，应按真实输入处理其保密性。

## 2. 威胁模型与信任边界

| 边界 | 典型威胁 | 已实现控制 | 未覆盖部分 |
| --- | --- | --- | --- |
| 浏览器 → 本机 HTTP | 伪造请求、跨站提交、旧标签重复确认 | 回环监听、严格 Host/Origin、CSRF、请求版本和确认 token | 本机原生程序可自行构造这些请求；没有用户登录 |
| 中文输入 → OperationRequest | 缺字段、负金额、同名或部分姓名、歧义 | 规则解析、补充信息、金额/日期校验、明确选择账户尾号、网页首次收款人核对 | 不是通用语义理解；否定句和复杂表达未获得完整覆盖 |
| Agent → 工具适配器 | 配置缺失、认证不足、风险变化、报价变化 | 工具白名单配置、认证、风险下限、服务端预览与确认前复验 | 没有真实适配器；接口声明不是对第三方服务的实际认证 |
| 已预览 → 有副作用的执行 | 旧摘要、重复执行、不明结果重试 | 摘要绑定、有效期、单次幂等键、先审计、执行后查询 | 业务状态和幂等记录未持久化，无数据库事务 |
| 运行内存 → 本地日志 | 敏感信息外泄、日志被改、磁盘写失败 | 标识符 HMAC、受控事件字段、SHA-256 链、写入 fsync、失败处理 | 没有日志加密、外部锚定、WORM、轮转或备份 |

## 3. 本机 HTTP 与前端

实现位置：[web_app.py](../banking_agent/web_app.py) 的 `LocalBankServer`、`LocalBankHandler`、`BrowserSession`；前端为 [app.js](../banking_agent/web/app.js)。

- 服务构造函数只接受 `127.0.0.1`，默认选择空闲端口。请求的 `Host` 必须精确等于 `127.0.0.1:当前端口`；不能把 URL 改成公网域名或局域网地址后直接作为多人服务使用。
- 静态资源只按 `/`、`/app.css`、`/app.js`、`/favicon.svg` 的固定映射读取，不拼接任意用户路径。未知路径返回 404。
- `GET /api/state` 为浏览器建立随机会话。Cookie 为 `HttpOnly; SameSite=Strict; Path=/; Max-Age=28800`，服务端保存其对应的独立 Agent、模拟银行和审计文件。会话上限 30，超出时按最近使用时间淘汰最旧会话；30 分钟无活动的会话会被回收，不再出现“占满后必须重启服务”。
- 修改入口仅为 `POST /api/message`，要求精确同源 `Origin`、`application/json`、有效会话及匹配的 `X-CSRF-Token`。请求体为非空 JSON 对象，大小限制为 20000 字节，正文读取超时 8 秒；普通指令长度为 1 至 3000 字。
- 每个会话用 `RLock` 串行处理状态读取和指令，`revision` 阻止旧标签提交；请求编号与完整内容指纹绑定。相同编号和内容只返回当前快照，内容发生变化则拒绝。
- 返回 `Cache-Control: no-store`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`；CSP 限制脚本、连接和字体为本站，并禁止被 iframe 嵌入。样式仍允许 `'unsafe-inline'`，不应描述为完全禁止内联内容的 CSP。
- 前端通过 `createElement` 与 `textContent` 展示文本，避免把聊天内容作为 HTML 插入；按钮忙碌状态可以减少连击。真正的重复执行保护仍在服务端。

本机使用明文 HTTP，没有 TLS、`Secure` Cookie、登录、退出登录、会话绝对有效期和频率限制。以上控制不能替代面向公网的 Web 安全设施。

## 4. 认证、风险与任务所有权

实现位置：[models.py](../banking_agent/models.py)、[policy.py](../banking_agent/policy.py)、[agent.py](../banking_agent/agent.py)、[demo.py](../banking_agent/demo.py)。

1. 非公共查询至少要求 `STANDARD`，所有变更至少要求 `ENHANCED`；风险达到 R3 的查询再要求增强认证。公共信息走独立公开工具，不查询账户。
2. `effective_risk()` 取操作风险下限与适配器评估的较高值；要求人工审核的请求被提升到 R4，调用方不能通过提交较低等级覆盖下限。
3. R4 变更在用户确认后进入模拟审核队列，不直接执行；R4 查询暂停并提交审核，不先返回账户数据。演示审核仅支持等待、取消与模拟拒绝，没有批准后执行路径。
4. 任务查询、确认、取消、补充、恢复等接口用 `user_id + session_id + task_id` 检查所有权。网页会话另有随机 Cookie 与独立对象隔离。
5. 跨渠道会使待处理的旧确认失效，重新认证并生成新摘要，不把 IM 的认证结果直接沿用于 APP 资金操作。

这些是模拟等级和任务所有权检查；网页会话使用 `demo-user` + 每会话独立的 `web-<随机>` 会话标识，模拟银行适配器与该标识绑定，其他人无法用别的 `user_id`/`session_id` 通过认证。仍然没有真实账号、密码、MFA、审核员登录或完整 RBAC。

认证等级只由服务端会话状态决定：`SimulatedBank.bind_channel_source()` 读取服务端渠道，`OperationRequest.channel` 不再作为认证依据；从 IM 升级到 APP 必须通过 `AuthChallenge` 校验一次性 6 位演示安全码，聊天中的“切换到APP”不会提权。

## 5. 预览、授权与确认

标准 `BankingAgent` 对变更生成服务端预览，包含金额、费用、收付款尾号、执行时间与影响。预览公开字段和风险等级、flags、审核标记、规则编号被序列化后计算 SHA-256 摘要；确认默认有效期为 300 秒。确认短语必须匹配当前操作，确认时重新认证、评估风险并获取预览，任何摘要变化都会要求重新确认。

网页还计算确认 token，绑定当前会话的 CSRF 随机值、任务编号、预览、风险等级与有效期；旧标签 `revision` 不匹配或 token 不匹配时返回 409。token 是服务端状态绑定机制，不是对外可验证的数字签名。

当前存在三类明确的演示授权例外，不能笼统写成“所有变更都二次确认”：

| 例外 | 实现与仍保留的限制 |
| --- | --- |
| 网页小额即时转账 | `BrowserDemoAgent._direct_transfer_authorized()` 仅接受 `0 < 金额 < 3000`、CNY、零费用、单次、立即、收款人已解析、非 R4 且无需人工审核的请求；金额至多两位小数。核心 `_try_direct_transfer()` 再做增强认证、风险与报价复验。摘要变化回到确认。普通核心与命令行不启用此例外。 |
| 虚构股票买入 | 归入 `INVESTMENT/buy_stock`。2026-11-01 加固版起**不再走范围授权直通路径**：必须生成服务端预览并由用户点击“确认投资操作”，与转账同一确认门。 |
| 计划范围/持续授权 | 计划先经确认建立。采购逐次检查商户、商品、单次金额、累计预算、剩余预留、次数和有效期，R4 信号不会因在授权范围内而消失。一次性授权仍逐次确认。 |

### 首次收款人核对

网页在首次新姓名或未核对样例出现时暂停原转账任务，创建随机核对 token；此时不保存新联系人、不付款。弹窗核对中文姓名、虚构银行和 4 位账户尾号。确认请求须匹配当前任务、待核对 token 和会话版本；同名已有账户还要求尾号匹配。身份确认审计成功后，联系人保存为本轮已核对状态，再补充到原任务并重新走认证、风险和金额规则。

普通即时金额小于 3000 元时，身份确认后可付款；3000 元及以上继续等待转账摘要确认；风险异常仍暂停或审核。取消不新增联系人、不付款。联系人会话内保存，刷新可恢复，重置/重启/独立会话不继承。这里的“身份核对”只是操作者批准虚构姓名与尾号，不验证身份所有权，不是 KYC 或收款账户实名核验。

## 6. 执行、幂等与异常

`_execute_once()` 先写执行事件，再把任务设为 `PROCESSING`，使用唯一幂等键调用工具。工具超时或抛异常时不自动再次提交，而以同一个键查询状态。没有可信结果就显示 `UNKNOWN`，不把“已提交”当成“已完成”。模拟工具自身也保存幂等键对应结果。

Web 请求编号防同一 HTTP 操作重复；核心 request_id 防相同调用重复创建任务；执行幂等键防重复提交工具。这三层范围不同：用户另发一个新编号的新指令仍被视为新交易，不自动识别其是否源于误点。

执行前审计失败会阻止本次副作用；已提交后审计或状态查询失败可能处于未知状态，不能承诺回滚已完成动作。跨商品采购逐笔审计，后续失败则停止后续步骤，不重提已经成功的订单。组合工作流只在依赖成功后继续，取消不会撤销已经完成的交易。

这些行为以单进程、内存模拟适配器为边界；没有跨进程锁、持久事务、崩溃恢复或真实支付对账。

## 7. 数据最小化与审计

实现位置：[privacy.py](../banking_agent/privacy.py)、[audit.py](../banking_agent/audit.py)、`BankingAgent._audit()`。

- 结构化输入拒绝 password、PIN、OTP、CVV、API key、完整账号等敏感字段名；只记录字段路径，不把被拒绝值写入审计。
- 查询/预览公开结果递归去掉秘密字段并遮盖长数字，保留有效日期；账户以尾号展示。此策略基于字段名和正则，不等同于全面个人信息识别。
- 核心审计不记录原始自然语言和原始 payload，记录固定操作摘要、金额、币种、尾号、任务/规则/工具/状态、确认摘要等；用户、会话与收款姓名用 HMAC-SHA-256 标识化。标识化不是加密。
- 每条 JSONL 事件包含前一条散列，追加时 `fsync`，重新打开时校验已有链。HMAC 保护的是标识符；事件链本身使用普通 SHA-256，没有外部可信锚点或数字签名，不能防整体重算、合法前缀截断或文件删除。
- 演示构建使用代码中公开的固定演示 HMAC key；独立核心入口可从配置指定环境变量读取 key，但不包含真实工具接入。不得把演示 key 当作保密凭据。
- **聊天原文例外：**`BrowserSession.messages` 在内存保存用户输入并返回快照，前端原样显示。这条路径没有对所有自由文本做脱敏。不要输入真实身份证、密码、银行卡或个人地址；上传 GitHub 时排除运行日志、聊天截图、临时文件和个人路径信息。
